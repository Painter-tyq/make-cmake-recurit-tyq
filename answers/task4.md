# Task 4：思考题

## 1. Make 和简单的 build.sh 有什么区别？

build.sh 每次运行，都会从头到尾执行全部 gcc 编译命令，所有源文件全部重新编译。
Make 支持**增量编译**，会对比文件修改时间，只重新编译发生改动的文件，没有改动的文件跳过编译，大幅节省编译时间；
同时 Make 可以自动处理文件之间的依赖关系（源文件、头文件改动后自动判断哪些需要重编）。

## 2. CMake 是编译器吗？

执行 `cmake --build build` 时，最终是谁在编译 C 源文件？

CMake **不是编译器**。CMake 是构建系统生成器，作用是根据 CMakeLists.txt 生成 Makefile（或其他构建文件）。
执行 `cmake --build build` 的时候，底层调用 make，**真正完成C源码编译成机器码的是 gcc 编译器**。

## 3. 为什么不希望每次都重新编译所有 `.c` 文件？

编译耗时很长，50个文件全部重新编译会浪费大量时间；
只修改1个文件，其余49个文件编译产物没有变化，没必要重复编译。使用增量编译，只重编改动的那一个文件，再重新链接，极大提升大型项目的编译效率。
